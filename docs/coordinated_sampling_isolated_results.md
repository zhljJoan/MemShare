# Coordinated Boundary-Decay 独立验证结果

更新时间：2026-08-03

分支：`coordinated-sampling-test`

基线提交：`454ff32`（`master`）

## 1. 当前可以得出的结论

Coordinated Boundary-Decay 是一个真实改变远程访问量、且在当前实现上能够缩短
训练关键路径的候选策略。它不是“完全无损”的方法：WIKI 和 LASTFM 的最终 test
AP 在三 seed 平均下分别下降 0.1363 和 0.2173 个百分点；WikiTalk 基本持平，
Flight 则有正向变化。因此当前只把它列为下一步验证方案，不把它定为期刊主方法。

该方法当前只改变 boundary-decay 的随机数耦合方式。本分支没有启用残差预测、
edge feature cache、hard negative、统一请求规划器、动态热点或迁移。

## 2. 方法与概率语义

baseline 对每个 root-occurrence 使用独立随机数：

$$
z_{r,i}=\mathbb I[U_{r,i}<p_{r,i}].
$$

coordinated 方法在同一 batch、layer 和 root group 内，让相同远程对象共享一个
keyed random number：

$$
U_{b,l,g,i}=\operatorname{HashUniform}(b,l,g,i),
$$

$$
z_{r,i}=\mathbb I[U_{b,l,g,i}<p_{r,i}].
$$

每个 occurrence 仍然与自己的原始概率比较，并没有把较小概率改成组内最大概率：

$$
\Pr(z_{r,i}=1)=p_{r,i}.
$$

如果同一对象的两个 occurrence 满足

$$
p_1<p_2,
$$

共享随机数只使选中事件嵌套：

$$
z_1\le z_2.
$$

对象至少被请求一次的概率从

$$
1-(1-p_1)(1-p_2)
$$

变为

$$
\max(p_1,p_2).
$$

这保持 occurrence 级边际概率，但会改变跨 root 的联合分布和梯度相关性。原生
Monte Carlo 测试已经覆盖相同概率与不同概率两种情况，结果为 `2 passed`。

## 3. 实验设置

- 两台机器，每台 4 张 GPU，共 8 卡；
- 固定图划分、固定热点与固定 ownership；
- `NCCL_NET=Socket`、`NCCL_IB_DISABLE=1`；
- `NCCL_SOCKET_IFNAME=ens4f1np1`；
- 训练使用 10GbE，launcher 同时检查日志中不存在 `NET/IB`；
- baseline 为 `boundery_recent_decay`；
- coordinated 为 `boundery_recent_decay_coordinated`，group size 为 8；
- 两种策略使用相同 seed 配对；
- WIKI、LASTFM、WikiTalk、Flight 使用 6773、6774、6775 三个 seed；
- GDELT、StackOverflow 当前使用 seed 6773，属于单 seed 大图初筛；
- WIKI/LASTFM 运行 50 epoch，其余四个数据集运行 10 epoch；
- 效率均值排除第 1 个 warm-up epoch，质量使用最后一个 epoch；
- AP/AUC 的变化统一使用“百分点”，效率和对象数变化使用百分比。

网卡字节来自两端 `ens4f1np1` 计数器的配对差值。它包含初始化、训练和评估期间的
Socket 流量，不等价于仅训练 payload；phase timer 是存在重叠的 host-wall 计时，
不能彼此相加得到 epoch 时间。

WIKI 的 route 与 launch 百分比上升对应的绝对增量分别只有约 1.476 ms/epoch 和
0.043 ms/epoch。当前 coordinated 实现减少的是组内相同远程对象的联合选中率，
没有减少每 batch 的 collective 次数；route 仍需构造和分桶请求，同时 keyed
random 与改变后的对象形状会改变 pipeline 重叠。因此不能仅由远程对象数下降推导
route/launch 必然同步下降。

## 6. 收敛性

以每个 baseline seed 的最佳 validation AP 的 99% 作为配对 target：

| 数据集 | 到达 target 的 epoch 变化 | 到达 target 的累计训练时间变化 |
| --- | ---: | ---: |
| WIKI | -3.67 ± 5.03 | -11.62% ± 10.30% |
| LASTFM | +2.00 ± 6.08 | +6.05% ± 19.78% |
| WikiTalk | -0.33 ± 0.58 | -8.47% ± 10.99% |
| Flight | -1.67 ± 2.08 | -23.99% ± 24.31% |
| GDELT | 0 | -2.52% |
| StackOverflow | 0 | -0.54% |

LASTFM 的 time-to-target 没有形成稳定收益；其最终 AP 也有轻微下降，是后续 group
size 与分层采样验证的重点。Flight 的正向结果存在较大的 seed 波动，不能只用均值
将其表述为精度提升机制。

GDELT 和 StackOverflow 在第 1 个 epoch 就超过“baseline 最佳 validation AP 的
99%”门槛，因此其 epoch 变化均为 0，该 target 对这两个高初始 AP 数据集缺乏
区分度。这里的累计训练时间变化实际上只是第 1 个 epoch 的时间变化，不能用于
证明后续收敛更快。

## 8. 当前判断与下一步门槛

当前建议是“保留、继续验证”，而不是“已敲定”：

1. 六个数据集的训练关键路径均下降，远程对象和网卡流量也均下降，说明策略有真实
   系统价值；其中只有前四个数据集完成了三 seed；
2. occurrence 级边际概率保持不代表训练完全无损，因为共享随机数会改变联合分布、
   estimator covariance 和同一 batch 内的梯度相关性；
3. WIKI/LASTFM 的小幅精度下降要求继续测试 group size 1/4/8/16；
4. 可以进一步按 GNN layer、root 类型或 burst 层级限制共享范围，使浅层或高风险层
   使用更小 group；
5. 在精度门槛满足前，不把当前 group-size 8 配置直接升级为期刊主方法。
6. GDELT 与 StackOverflow 还需要补足另外两个 seed，当前单 seed 结果只用于判断
   是否值得继续推进。

原始逐 epoch 指标位于本地实验目录
`outputs/coordinated_sampling_isolated/20260803/`，该目录不提交到 Git。
