# 分层去重结构与计算 Kernel 设计（初稿）

> 版本：v0.2，2026-09-03  
> 范围：依据当前工作区中的采样、时序卷积、记忆更新与四卡单 epoch 实验整理，并补充紧凑 K/V 分段注意力的端到端开关对照。本文先讲可用于论文的主线，再单独说明当前实现和证据边界。

## 0. 核心观点

时序图训练中的问题不只是“输入里有重复项”，而是同一份信息会沿着 **采样、跨卡读取、状态更新和图卷积** 被逐层展开：

- 同一个节点的静态特征和历史记忆会被多个时间状态重复引用；
- 同一个时间状态会被多条采样记录重复引用；
- 同一个 eid 的特征也可能被多条采样记录重复引用；
- 但每条采样记录参与的目标节点、采样 $\Delta t$ 和 softmax 分组不同，因此不能直接删掉。

普通去重只解决“相同对象少取几次”。如果后续仍把对象重新展开成逐状态、逐采样记录的大张量，再执行拼接、线性层、softmax 和聚合，去重收益会被反复的索引、展开、中间张量写回和 kernel 启动抵消。

因此本文的主张不是“使用一次 unique”，而是：

> 将节点/边对象、带时间的节点状态和采样记录分别保存，并让后续算子直接消费这三层表示；对象只读取一次，状态只计算一次，采样记录只保留必要的拓扑索引。

## 1. 去重的 Motivation

### 1.1 一个具体例子

假设一个 batch 中保留了下面四条采样记录：

| 采样记录 | 源状态 | 目标状态 | eid | 采样 $\Delta t$ |
| --- | --- | --- | --- | ---: |
| 0 | $node_{A,8}$ | $node_{B,10}$ | $eid_7$ | 2 |
| 1 | $node_{A,8}$ | $node_{B,10}$ | $eid_7$ | 2 |
| 2 | $node_{A,8}$ | $node_{C,10}$ | $eid_9$ | 2 |
| 3 | $node_{A,6}$ | $node_{B,10}$ | $eid_7$ | 4 |

这里同时存在三种重复：

1. **对象重复**：节点 A 被多个时间状态引用，$eid_7$ 被三条记录引用；
2. **时间状态重复**：$node_{A,8}$ 被三条记录引用；
3. **拓扑位置重复**：记录 0 和记录 1 的内容相同，但它们仍是两次采样出现。

第三类不能直接删除。注意力在 $node_{B,10}$ 的三条入边上归一化；删除其中一次出现会改变 softmax 的分母，也就改变模型语义。真正可以复用的是前两类数据的读取和投影。

### 1.2 为什么时序图里重复会被放大

同一节点可能同时作为多个正样本端点、负样本端点和邻居出现。即使节点 ID 相同，只要查询时间不同，它们就是不同的时间状态；而同一个时间状态又可能被许多邻居记录引用。因此通常有：

$$
\text{节点对象数 } U_n \leq \text{时间状态数 } S \leq \text{采样记录数 } P.
$$

边侧也有：

$$
\text{边对象数 } U_e \leq \text{采样记录数 } P.
$$

如果从头到尾都使用逐记录布局，那么节点特征、边特征、历史记忆和线性投影都会按 $P$ 行反复处理。对于 TGN、APAN 这类单行计算量不高的模型，索引、拼接、显存读写、通信和 kernel 启动很容易比省下来的矩阵计算更显著。

## 2. 去重的两个层面

### 2.1 第一层：识别数据冗余，并保留三层状态

我们不使用一个“万能去重表”，而是保留三个粒度不同的表。

#### 层 A：对象表

每个节点和每个 eid 只保存一次，承载与查询时间无关的数据：

- 节点静态特征、历史记忆、mailbox；
- eid 特征；
- 对象属于哪张卡，用于跨卡读取。

对象表的行数分别为 $U_n$ 和 $U_e$。

#### 层 B：时间状态表

一个时间状态统一记为 $node_{u,t}$，其中 $u$ 是节点 ID、$t$ 是查询时间。$node_{A,8}$ 与 $node_{A,6}$ 是两个状态，两个 $node_{A,8}$ 则合并。该层承载：

- 查询时间和时间编码；
- 在该时间点得到的动态节点表示；
- 状态到节点对象的映射。

时间状态表的行数为 $S$。

#### 层 C：采样记录表

每次邻居采样出现都保留一行，只存：

- 源时间状态编号；
- 目标时间状态编号；
- eid 编号；
- 采样 $\Delta t$ 及训练角色。

采样记录数仍为 $P$。这一层不做语义去重，因为它定义了真实的邻接关系、出现次数、顺序和注意力分组。

对前面的例子，可以写成：

~~~text
节点对象表：  [A, B, C]
边对象表：    [eid_7, eid_9]

时间状态表：  [node_{A,8}, node_{A,6}, node_{B,10}, node_{C,10}]
状态→节点：   [A,   A,   B,    C]

采样记录→源状态： [node_{A,8}, node_{A,8}, node_{A,8}, node_{A,6}]
采样记录→目标状态：[node_{B,10},node_{B,10},node_{C,10},node_{B,10}]
采样记录→eid：    [eid_7, eid_7, eid_9, eid_7]
~~~

一句话概括是：

> 对象只存一次，时间状态只算一次，拓扑出现全部保留但只保存索引。

### 2.2 第二层：建立能被后续算子直接消费的结构

只做普通去重时，常见执行链是：

~~~text
逐记录数据
  → 找唯一对象/状态
  → 读取或计算紧凑结果
  → 按反向索引展开
  → 拼接成逐记录输入
  → 调用通用算子
  → 聚合或映射回状态
~~~

这条链虽然减少了部分读取，却产生了新的开销：

- 按映射执行 gather / index-select；
- 把节点、边和时间分量拼成更宽的逐记录张量；
- 物化逐记录的 Query、Key、Value、注意力分数和加权消息；
- 在反向传播中通过 scatter / atomic-add 合并共享对象的梯度；
- 多个短 kernel 之间反复读写显存。

为了说明这里的“完整投影”和“后续计算”，先把当前 TGN 时序卷积简化为四个阶段；完整公式见第 3 节：

1. **逐记录准备输入**：对第 $p$ 条采样记录，根据索引取出源时间状态 $h_{a(p)}$、边特征 $f_{o(p)}$ 和时间编码 $\phi(\Delta t_p)$，拼成 $x_p=[h_{a(p)}\Vert f_{o(p)}\Vert\phi(\Delta t_p)]$。这一阶段的 gather 不是可学习的模型层，只是在为投影准备输入；$P$ 条记录会生成 $P$ 行 $x_p$。
2. **Q/K/V 线性投影**：目标时间状态生成 Query；每条记录分别计算 $k_p=W_Kx_p+b_K$ 和 $v_p=W_Vx_p+b_V$，因此 Key 和 Value 都是 $P$ 行。
3. **逐记录注意力与按目标聚合**：每条记录计算一次分数，在同一目标状态的入边内做 softmax，再对 $v_p$ 加权求和。这里不能删除重复出现的记录，因为每次出现都会改变 softmax 和聚合结果。
4. **输出变换**：聚合结果与目标状态表示一起经过输出线性层、激活和归一化，得到新的目标状态表示。

在这个计算链中，“把 gather 和线性层写进一个 kernel”指的是把前两阶段的局部操作融合：kernel 不再显式生成 $P$ 行 $x_p$，而是按索引读取三类输入后直接计算 $k_p$ 和 $v_p$。它省掉了逐记录拼接张量的写入和再次读取，但仍对每个 $p$ 执行一遍完整的 K/V 投影，并向注意力层输出 $P$ 行 Key 和 $P$ 行 Value。如果多条记录引用同一个源时间状态或 eid，它们的共享部分仍会被重复投影。

真正保持紧凑表示的做法，是分别按 $S$ 个时间状态、$U_e$ 个边对象和 $P$ 个时间编码计算投影；注意力 kernel 扫描记录时再通过映射读取并相加，而不提前物化 $P$ 行完整 K/V。这样，共享的状态和边投影在连续算子之间始终保持为 $S$ 行和 $U_e$ 行，只有不可避免的逐记录时间项、打分和 softmax 保持 $P$ 规模。

新结构把三张表和它们的映射定义为整个 batch 生命周期内的共同接口：

~~~text
采样器
  → 一次构造对象表、时间状态表、采样记录表及映射
  → 按对象表跨卡读取
  → 按对象/时间状态粒度更新记忆
  → 卷积 kernel 按索引直接读取紧凑投影
  → 按目标状态分段完成注意力与聚合
~~~

关键区别是：

> 普通去重是“少算一些输入行，再展开回通用布局”；新结构是“让多个连续算子共同使用紧凑布局，避免在算子之间恢复冗余布局”。

## 3. 时序卷积中重复发生在哪里

下面分析当前 TGN 使用的非分离式多头时序注意力。时间状态写作 $node_{u,t}$。设第 $p$ 条采样记录的源状态、目标状态和 eid 分别为 $a(p)$、$b(p)$、$o(p)$，采样 $\Delta t$ 记为 $\Delta t_p$，其时间编码为 $\phi(\Delta t_p)$。

### 3.1 原始计算公式

对目标状态，查询向量为：

$$
q_d=W_Q[h_d\Vert\phi(0)]+b_Q.
$$

对每条采样记录，Key 和 Value 为：

$$
k_p=W_K[h_{a(p)}\Vert f_{o(p)}\Vert\phi(\Delta t_p)]+b_K,
$$

$$
v_p=W_V[h_{a(p)}\Vert f_{o(p)}\Vert\phi(\Delta t_p)]+b_V.
$$

每个头在目标状态的入边集合 $\mathcal N(d)$ 内做归一化：

$$
e_{p,h}=\operatorname{LeakyReLU}(q_{b(p),h}^{\mathsf T}k_{p,h}),
$$

$$
\alpha_{p,h}=\frac{\exp(e_{p,h})}
{\sum_{j\in\mathcal N(b(p))}\exp(e_{j,h})},
\qquad
z_{d,h}=\sum_{p\in\mathcal N(d)}\operatorname{Dropout}(\alpha_{p,h})v_{p,h}.
$$

最后把各头的结果与目标状态自身表示拼接，经过输出线性层、ReLU 和归一化得到新表示。

### 3.2 可复用与不可复用的部分

| 计算 | 原布局 | 是否能复用 | 原因 |
| --- | ---: | --- | --- |
| 目标 Query 投影 | $D$ 行投影，随后展开到 $P$ 行 | 可以避免展开 | 同一目标的 Query 对所有入边相同 |
| 源状态对 K/V 的贡献 | $P$ 行 | 可按 $S$ 行投影 | 同一源时间状态被多条记录引用 |
| eid 特征对 K/V 的贡献 | $P$ 行 | 可按 $U_e$ 行投影 | 同一 eid 的特征不随出现位置改变 |
| 采样 $\Delta t$ 对 K/V 的贡献 | $P$ 行 | 当前仍按 $P$ 行 | $\Delta t$ 属于具体采样记录 |
| 打分、softmax、dropout、加权和 | $P$ 行 | 不能删除记录，但可以融合 | 每次出现都影响目标分组的归一化与聚合 |

最明显的重复发生在原实现构造下面两个逐记录输入时：

$$
[h_{a(p)}\Vert f_{o(p)}\Vert\phi(\Delta t_p)],\quad p=1,\ldots,P.
$$

即使 $h_{a(p)}$ 和 $f_{o(p)}$ 已经存在于紧凑表中，通用线性层仍会把它们 gather、拼接，并在 K、V 两次线性投影中重复计算。

### 3.3 等价的分解公式

线性层对拼接输入可以按列分块：

$$
W_K=[W_K^H\;W_K^F\;W_K^T],
\qquad
W_V=[W_V^H\;W_V^F\;W_V^T].
$$

因此原公式严格等价于：

$$
k_p=\underbrace{W_K^Hh_{a(p)}}_{\text{按时间状态算一次}}
+\underbrace{W_K^Ff_{o(p)}}_{\text{按边对象算一次}}
+\underbrace{W_K^T\phi(\Delta t_p)+b_K}_{\text{按采样记录计算}},
$$

$$
v_p=\underbrace{W_V^Hh_{a(p)}}_{\text{按时间状态算一次}}
+\underbrace{W_V^Ff_{o(p)}}_{\text{按边对象算一次}}
+\underbrace{W_V^T\phi(\Delta t_p)+b_V}_{\text{按采样记录计算}}.
$$

忽略 Query、非线性、访存与反向传播时，K/V 投影的行计算量可从近似

$$
C_{\mathrm{expanded}}\propto 2P(d_h+d_e+d_t)d_o
$$

变为

$$
C_{\mathrm{compact}}\propto
2(Sd_h+U_e d_e+Pd_t)d_o.
$$

这里前面的 2 表示 K 和 V 两套投影。这个公式只是理论工作量，不等于端到端加速比；索引读取、逐项相加、padding、反向原子累加以及小 batch 的启动成本都可能抵消收益。

## 4. 去重结构如何构建

### 4.1 在采样边界一次生成三层表示

当前训练路径在采样器仍持有原始采样记录时完成紧凑化：

1. 每个采样线程先用哈希表合并本线程重复的 $node_{u,t}$ 和 eid；
2. 主合并阶段先放入 root 状态，再按线程顺序和首次出现顺序稳定合并；
3. 节点对象和边对象按 owner 卡分组，直接形成跨卡读取需要的顺序；
4. 同时生成状态到对象、root 到状态、采样记录到源/目标状态、采样记录到边对象的映射；
5. 原始采样记录的数量、顺序、eid、采样 $\Delta t$ 和训练角色保持不变。

这样避免了采样返回后再执行全局唯一化、首次出现位置恢复、元数据重映射和多轮高层张量重建。

### 4.2 面向目标节点保存分段计划

卷积需要在每个目标状态的入边内做 softmax。结构构建阶段将采样记录组织为按目标分段的稀疏格式，并保存：

- 每个目标分段的起止指针；
- 稀疏格式中的记录顺序到原采样顺序的置换。

需要强调：当前实现仍由图框架完成 COO 到 CSC 的准备；新结构没有消灭这次转换。它的作用是把本 batch 的分段计划显式交给后续融合 kernel 复用。

## 5. 对应 Kernel 如何设计

### 5.1 仅融合逐记录投影：解决拼接，不解决重复计算

代码中保留了一条逐记录融合投影路径：kernel 根据“记录→源状态”和“记录→边对象”的索引直接读取三类输入，在寄存器中完成线性层，避免显式构造拼接张量。

但它仍为 $P$ 条记录各计算一次完整 K/V，并输出 $P$ 行结果。所以它适合作为“kernel 内 gather + concat 融合”的对照，不是最终的跨记录复用方案。

### 5.2 分段注意力 Kernel：保留所有记录，融合注意力流水线

当前四卡 TGN 新结构实验实际启用的是这条路径。它接收按目标组织的 Query、逐记录 K/V 和分段指针，每个“目标状态 + 注意力头”启动一个程序，分块扫描该目标的所有入边。

kernel 使用在线 softmax。若当前累计最大值、分母和加权和为 $m,l,r$，读入一块分数后更新为：

$$
m'=\max(m,\max e),
$$

$$
l'=l\exp(m-m')+\sum_p\exp(e_p-m'),
$$

$$
r'=r\exp(m-m')+\sum_p\operatorname{Dropout}(\exp(e_p-m'))v_p,
\qquad z=r'/l'.
$$

这样把“打分、LeakyReLU、最大值归约、指数、分母归约、dropout、Value 加权和、目标聚合”合并在一次分段扫描中，不再物化完整的注意力分数、归一化权重、加权 Value 和消息张量。

反向 kernel 根据前向保存的 log-sum-exp 重算权重，生成 Query、Key、Value 梯度。采样记录没有被删除，只是计算和中间数据流被融合。

### 5.3 紧凑投影 + 分段注意力 Kernel：完整消费三层表示

当前代码还实现了更进一步的路径：

1. 将 K、V 的权重合并后，分别对 $S$ 行时间状态、$U_e$ 行边对象和 $P$ 行时间编码做一次投影；
2. 不提前生成 $P$ 行完整 K/V；
3. 分段注意力 kernel 扫描第 $p$ 条记录时，根据两个映射读取对应的状态投影和边投影，再与该记录的时间投影相加；
4. 在寄存器中直接完成打分、在线 softmax 和 Value 聚合；
5. 反向传播用原子加法把多个记录的梯度累加回共享状态和边对象。

这条路径才完整实现了“对象/状态层做可复用投影，记录层只保留索引和不可避免的注意力计算”，并避免逐记录 K/V 的物化。

这里的“合并到一个 kernel”具体指：状态/边/时间三类紧凑投影完成后，把按映射读取、K/V 分量相加、打分、在线 softmax、dropout 和 Value 聚合放入同一个分段注意力 kernel。三类紧凑表本身的稠密线性投影仍由前置 GEMM 完成；若把这些投影也塞入逐记录注意力 kernel，会重新为每条记录计算共享分量，违背投影复用的目的。

原四卡单 epoch 的 `new_structure` 配置没有开启这条路径。2026-09-03 的补充实验在相同 gpu07、相同 TGN 新结构配置上只增加 `--compact_kv_projection on`，并使用更新后的 `edge_ids` 直接寻址接口：kernel 不再要求调用方先把三类投影按 CSC 顺序 `index_select` 成新的 $P$ 行副本。第 7 节给出端到端结果；四个数据集中三个加速、一个轻微回退，因此当前证据支持“收益依赖工作负载”，不能写成普遍加速。

更新接口的局部前向+反向测试中，预先生成三个 $P$ 行 CSC 重排副本的路径为 2.828 ms，kernel 直接按 `edge_ids` 寻址为 2.378 ms，降低 15.93%。这个数字只隔离“取消预重排副本”的收益；第 7 节的四卡结果才衡量相对物化完整 $P$ 行 K/V 的端到端效果。

### 5.4 紧凑 GRU Kernel：对象分量算一次，时间分量按状态算

TGN 的记忆更新也存在对象到时间状态的重复展开。设状态 $s$ 对应节点对象 $u(s)$，mailbox 为 $m_u$，历史记忆为 $h_u$，状态时间编码为 $\tau_s$。标准 GRU 的输入是 $[m_{u(s)}\Vert\tau_s]$。

当前实现将门投影拆为：

$$
g^m_u=W_{ih}^{m}m_u,
\qquad
g^t_s=W_{ih}^{t}\tau_s+b_{ih},
\qquad
g^h_u=W_{hh}h_u+b_{hh}.
$$

mailbox 和 hidden 两部分按 $U_n$ 个对象计算，时间部分按 $S$ 个状态计算。随后一个逐状态 kernel 通过“状态→对象”映射读取三组门值，完成：

$$
r_s=\sigma(g^m_{u(s),r}+g^t_{s,r}+g^h_{u(s),r}),
$$

$$
z_s=\sigma(g^m_{u(s),z}+g^t_{s,z}+g^h_{u(s),z}),
$$

$$
n_s=\tanh(g^m_{u(s),n}+g^t_{s,n}+r_s\odot g^h_{u(s),n}),
$$

$$
h'_s=n_s+z_s\odot(h_s-n_s).
$$

kernel 把索引读取、三个门的逐项运算和输出写回融合起来；反向传播把共享对象分量的梯度原子累加回对象表。它没有合并不同时间的状态，只复用其中与时间无关的仿射投影。

### 5.5 APAN 的紧凑记忆注意力

APAN 当前走反向/恒等采样链路，尚未接入 TGN 使用的采样器内三层构造和图卷积分段路径。本轮所谓 APAN“新结构”只在记忆注意力中复用对象级 mailbox、memory 投影，并用等长分段注意力融合每个状态对固定大小 mailbox 的 softmax 和聚合。

因此 APAN 结果应称为“紧凑记忆消费者”的结果，不能表述为完整三层结构在 APAN 上的端到端结果。

## 7. 四卡单 epoch 实验结果

硬件均为单机 4 张 NVIDIA A40。每个配置只运行 epoch 0，关闭验证、测试和 checkpoint；数值取四个 rank 中最大的训练时间。计时包含首次 kernel/JIT 开销，不包含数据加载和图构建初始化。紧凑 K/V 补充列只适用于 TGN，于 2026-09-03 在原实验主机 gpu07 上运行；共同参数和请求工作量与对应的 `new_structure` 行一致，唯一新增开关为 `--compact_kv_projection on`。

这里必须区分两种“不去重”：

- **全链路不去重（极端消融）**：节点/eid 的通信请求和 $node_{u,t}$ 状态都不去重；
- **普通不去重（主要基线）**：节点/eid 的通信与对象读取仍然去重，只关闭 $node_{u,t}$ 状态合并；对应 `--block_dedup on --state_dedup off`。

此前 1670.200417 s 的 GDELT/TGN 属于前一种极端消融，不能把它与普通去重之间的全部差值都归因于状态去重。补充的普通不去重在 gpu06 上运行，原三组在 gpu07 上运行；两台机器均为 4 × A40，但跨主机百分比只能用于判断趋势。

结果支持五点：

1. 普通不去重避免了通信请求放大；以它为基线，TGN 的普通状态去重初步降低 25.50%–33.76%，说明 $node_{u,t}$ 冗余本身仍是显著开销；
2. APAN 的普通状态去重初步降低 0.75%–12.06%，收益小于 TGN，符合其 identity/reversed 图路径的工作量构成；
3. 新结构在 WikiTalk、StackOverflow 和 GDELT 上相对普通去重继续加速，TGN 的增益随工作负载增大而更明显；
4. LASTFM 的 epoch 很短，首次编译、映射和融合 kernel 的固定成本没有被摊薄，因此新结构在 epoch 0 反而更慢。
5. 在新结构上进一步避免完整 $P$ 行 K/V 物化后，LASTFM、WikiTalk 和 GDELT 分别降低 19.30%、3.66% 和 6.91%，但 StackOverflow 回退 0.98%。四组补测的 local/remote node 与 edge 请求数均与对应 `new_structure` 日志完全一致，因此差异来自计算路径而非采样工作量；同时，结果表明该路径的收益不能只由数据集总规模推断。若把紧凑 K/V 视为完整 TGN 路径的一部分，则它相对普通去重在四个数据集上分别降低 0.95%、11.88%、9.76% 和 20.57%。

标有 `*` 的百分比跨 gpu06/gpu07，不能作为最终论文加速比；严格结论需要在 gpu06 上重跑普通去重和新结构。

当前不能声称“新结构在所有规模上都更快”。更稳妥的结论是：

> 普通去重负责消除数据读取层面的冗余；分层结构和结构感知 kernel 在中大型工作负载上进一步减少重复投影、中间张量与算子调度开销，但小工作负载需要直接路径或基于规模的回退策略。

对已经接入完整三层卷积路径的 TGN，本次单次 epoch-0 结果覆盖的四个数据集均快于普通去重；上述“不能声称全面更快”的限制仍适用于尚未接入该卷积路径的 APAN，以及缺少重复试验和稳态统计的证据范围。

## 8. 正确性与证据边界

当前实现保留以下语义不变量：

- 正负样本及其索引不变；
- 每条采样记录、eid、采样 $\Delta t$ 和目标分组不变；
- $node_{u,t}$ 完全相同才合并，节点相同但查询时间不同不合并；
- softmax 仍在同一目标状态的全部入边上计算；
- 输出公式和模型参数不变，只改变计算分解和归约顺序。

已有测试分别覆盖三层映射与旧结构对齐、分段注意力的前向/反向、非均匀度数和边置换、紧凑投影注意力的前向/反向，以及紧凑 GRU 与标准 GRU 的结果和梯度对齐。

本次补测前重新运行上述相关测试，共 16 项通过。

仍需注意：

- 原子累加和分段归约改变了浮点加法顺序，只能主张数值等价，不能主张逐 bit 相同；
- 紧凑投影注意力目前只验证了固定 dropout mask，对自动生成 mask 的随机数轨迹还需要独立验证；
- 四卡结果每个配置仅一次、仅 epoch 0，没有方差、稳态或尾部统计；
- 紧凑 K/V 补充列与原 `new_structure` 列在同一主机、同一工作量上运行，但日期不同且各只有一次；可以作为开关消融的初步证据，最终论文结果仍应交错重跑并报告多次统计量。

## 10. 可直接用于论文的总结段

时序图 batch 同时包含对象、时间状态和拓扑出现三个粒度。已有的直接去重虽然能够减少重复对象的读取，但后续通用算子仍需将紧凑结果展开为逐状态或逐边张量，由此产生重复投影、索引回填、中间张量写回和多 kernel 调度开销。我们将唯一节点/eid 对象、唯一 $node_{u,t}$ 状态与完整采样记录组织为一个贯穿 batch 生命周期的分层表示：跨卡通信按对象执行，时间相关更新按状态执行，注意力归一化与聚合按采样记录执行。基于这一表示，记忆更新将对象不变的仿射变换从状态计算中分离，时序卷积则利用线性层的可加分解复用状态与 eid 投影，并通过目标分段 kernel 融合 softmax 和聚合。该设计不删除任何采样记录，也不合并查询时间不同的节点状态，而是在保持 eid 和采样 $\Delta t$ 语义不变的前提下，使每类数据只在必要的粒度上计算和物化。
